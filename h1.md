# h1 Hei Ansiblen maailma

Ympäristö: Windows 10, VirtualBox, Debian 13.7 (xfce live -levykuva), 4 GB RAM, 2 CPU, 25 GB levy.
Tehty 27.10.2026.

## x) Lue ja tiivistä

### Karvinen 2026: SSH public key - Login without password
- `ssh-keygen` loi avainparin eli julkisen avaimen ja yksityisen avaimen.
- `ssh-copy-id` kopioi julkisen avaimen kohdekoneen tiedostoon `~/.ssh/authorized_keys`.
- Salasanaa ei kysytty enää, koska palvelin näkee, että avain löytyy authorized_keys-tiedostosta.
- Oma kysymys: miten SSH käytännössä toimii taustalla, kun avain tarkistetaan?

### Karvinen 2026: Hello Ansible
- Orjakone tarvitsee toimiakseen SSH-demonin ja Pythonin.
- `hosts.ini` on lista koneista, joita Ansible ohjaa.
- `site.yml` kertoo, mitkä roolit ajetaan millekin koneille.
- `changed=0` tarkoittaa, että mitään ei muuttunut. Se on idempotentti, eli Ansible tarkistaa ensin tilan eikä tee mitään, jos kaikki on jo kunnossa.
- Oma kysymys: miten tätä voi skaalata isommille määrille koneita?

## b) Sshecrets
```
sudo apt-get -y install ssh
sudo systemctl enable --now ssh
sudo systemctl status ssh --no-pager
ssh localhost
w
```
Ensimmäinen `ssh localhost` antoi virheen "Host key verification failed", koska en kirjoittanut vastaukseksi `yes`. Sen jälkeen tuli "Permission denied", joka johtui salasanan väärinkirjoituksesta. Toisella yrityksellä kirjautuminen onnistui.

## d) Hei Ansible
```
$ tree -F
./
├── ansible.cfg
├── hosts.ini
├── roles/
│   └── hello/
│       └── tasks/
│           └── main.yml
└── site.yml
```
```
ansible all -a 'uptime'
ansible-playbook site.yml
ssh localhost 'cat /tmp/hello-ansible'
ansible-playbook site.yml
```
Ensimmäinen ajo antoi `changed=1`, mikä tarkoittaa, että tiedosto luotiin. Toinen ajo antoi `changed=0`, koska tiedosto oli jo olemassa. `cat` tulosti "Hei Mikaelilta!".

Kotikansiossa ajettuna tuli "site.yml could not be found", koska Ansible etsii site.yml:ää siitä kansiosta, jossa olet.
