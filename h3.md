# h3 Demoni

Ympäristö: Windows 10, VirtualBox, Debian 13 (sama kone kuin h1:ssä ja h2:ssa). Tehty 10.11.2026.

## x) Lue ja tiivistä

### Karvinen 2026: Apache installed with Ansible - quick notes
- Package-file-service: daemonit asennetaan kolmessa vaiheessa. Ensin asennetaan paketti, sitten muokataan asetustiedostoja ja lopuksi käynnistetään palvelu, jotta muutokset tulee voimaan
- Roolin kansiot: files/ sisältää mestarikopiot tiedostoista, handlers/ palveluiden uudelleenkäynnistykset ja tasks/ suurimman osan Ansible-koodista
- Oma huomio: Apachen ja Nginxin asennus tuntui aika samalta, molemmissa oli samat vaiheet

### Ansible Community Documentation: Handlers
- Handler on tehtävä, joka ajetaan vain kun joku toinen tehtävä muuttaa jotain ja ilmoittaa siitä notify:llä
- Oma huomio: Fiksua, koska palvelin ei katkea turhaan joka ajolla

### ansible-doc service
- name on palvelun nimi, state on palvelun tila (started, stopped, restarted) ja enabled kertoo käynnistyykö palvelu bootissa
- Oma huomio: En tajunnut miten Caddy oli jäänyt päälle edelliseltä tunnilta. Syy oli se, että se oli enabled-tilassa ja käynnistyi aina bootissa

```
sudo systemctl enable --now apache2
```

Vianetsintä:
```
sudo journalctl -xeu apache2.service --no-pager | tail -20
sudo apache2ctl configtest
# Syntax OK
sudo ss -tlnp | grep ':80'
# LISTEN 0 4096 *:80 *:* users:(("caddy",pid=942,fd=6))
```

configtest näytti Syntax OK, eli asetuksissa ei ollut vikaa. Komennolla sudo ss -tlnp | grep ':80' huomasin, että Caddy oli jäänyt portille 80 viime kerralta. Kaksi demonia ei voi kuunnella samaa porttia (Karvinen 2026b), joten Apache ei päässyt käynnistymään.

Korjaus:
```
sudo systemctl disable --now caddy
sudo systemctl enable --now apache2
```

### Kotisivu tavallisen käyttäjän kansioon
```
mkdir ~/publicsite
echo "Mikaelin kotisivu, tehty ilman sudoa" > ~/publicsite/index.html
chmod ugo+x /home/mikael/
chmod ugo+x /home/mikael/publicsite/
chmod ugo+r /home/mikael/publicsite/index.html
```
chmod muuttaa oikeuksia. Apache pyörii käyttäjänä www-data, joka on mun tiedostoille "muut". Se tarvitsee x-oikeuden kansioihin, että pääsee kulkemaan niiden läpi, ja r-oikeuden tiedostoon, että voi lukea sivun (Karvinen 2026b).

<img width="1004" height="263" alt="image" src="https://github.com/user-attachments/assets/d74bde75-f845-4967-b723-3c0326b42c5c" />

### Virtuaalipalvelin
Tein asetuksen Karvisen mallin mukaan (Karvinen 2026a).
```
$ cat /etc/apache2/sites-available/mikael.conf
<VirtualHost *:80>
        ServerName mikael.example
        DocumentRoot /home/mikael/publicsite/

        <Directory /home/mikael/publicsite/>
                require all granted
        </Directory>
</VirtualHost>
```
```
sudo a2ensite mikael.conf
sudo a2dissite 000-default.conf
sudo apache2ctl configtest
sudo systemctl restart apache2
```
a2ensite ja a2dissite ovat komentorivityökaluja, joilla hallitaan Apachen virtuaalipalvelimia. a2ensite otti käyttöön mun sivun mikael.conf ja a2dissite poisti käytöstä Debianin oletussivun 000-default.conf, jotta etusivulla näkyy mun sivu.

## b) Moottorix

Sammutin Apachen ja asensin Nginxin:
```
sudo systemctl disable --now apache2
sudo apt-get -y install nginx
curl localhost
```

### Huomio: Nginx näytti Apachen sivua
curl näytti Apachen oletussivun HTML:n, vaikka olin jo sammuttanut Apachen. Tarkistin, kumpi palvelin oikeasti vastaa:
```
curl -sI localhost | grep -i server
# Server: nginx
sudo ss -tlnp | grep ':80'
systemctl is-active apache2 nginx
# inactive
# active
```
Se johtui siitä, että Nginxin oletusasetus käytti samaa kansiota /var/www/html/, jossa oli Apachen index.html.

<img width="1004" height="240" alt="image" src="https://github.com/user-attachments/assets/c96b2dfb-f7b8-49d7-bdf5-62e7c9e83cd5" />

### Nginxin asetus
```
$ cat /etc/nginx/sites-available/mikael
server {
        listen 80 default_server;
        listen [::]:80 default_server;
        server_name mikael.example;
        root /home/mikael/publicsite;
        index index.html;
}
```
```
sudo rm /etc/nginx/sites-enabled/default
sudo ln -s /etc/nginx/sites-available/mikael /etc/nginx/sites-enabled/mikael
sudo nginx -t
sudo systemctl restart nginx
```
rm poisti oletussivun linkin sites-enabled-kansiosta. ln -s teki linkin mun sivusta sites-enabled-kansioon, eli otti sen käyttöön samaan tapaan kuin a2ensite Apachessa. nginx -t testasi asetukset ennen uudelleenkäynnistystä, kuten apache2ctl configtest.

### Rooli
```
$ tree -F roles/nginx
roles/nginx/
├── files/
│   └── mikael
├── handlers/
│   └── main.yml
└── tasks/
    └── main.yml
```
```
$ cat roles/nginx/tasks/main.yml
- service:
    name: apache2
    state: stopped
    enabled: false
- apt:
    name: nginx
    state: present
- copy:
    src: mikael
    dest: /etc/nginx/sites-available/mikael
    owner: root
    group: root
    mode: "0644"
  notify: restart nginx
- file:
    src: /etc/nginx/sites-available/mikael
    dest: /etc/nginx/sites-enabled/mikael
    state: link
  notify: restart nginx
- file:
    path: /etc/nginx/sites-enabled/default
    state: absent
  notify: restart nginx
- service:
    name: nginx
    state: started
    enabled: true
```
```
$ cat roles/nginx/handlers/main.yml
- name: restart nginx
  service:
    name: nginx
    state: restarted
```
Nginx-rooli sammuttaa ensin Apachen, että portti 80 on vapaa, asentaa paketin, kopioi asetustiedoston ja käynnistää palvelun. Asetusten muutoksista ilmoitetaan handlerille notify:llä.
