## x) Lue ja tiivistä

### Chacon & Straub 2014: Pro Git, 1.3 What is Git?
- Git ei tallenna pelkkiä eroja, vaan tilannekuvan (snapshot) koko projektista jokaisessa commitissa. Jos tiedosto ei muuttunut, Git viittaa edelliseen versioon
- Melkein kaikki Git-toiminnot ovat nopeita, koska ne tehdään paikallisesti omalla koneella
- Tiedostolla on kolme tilaa: modified (muutettu), staged (merkitty seuraavaan committiin) ja committed (tallennettu paikalliseen varastoon)
- Oma huomio: Huomasin kolme tilaa itse git statusilla, kun c-kohdassa muutokset näkyivät ennen committia

### git add --all && git commit; git pull && git push
- `git add --all` lisää kaikki muutokset (uudet, muutetut ja poistetut tiedostot) staged-tilaan
- `git commit` tallentaa staged-muutokset paikalliseen varastoon viestin kanssa
- `git pull` hakee palvelimelta muiden tekemät muutokset ja yhdistää ne omiin
- `git push` työntää omat commitit palvelimelle eli GitHubiin
- `&&` ajaa seuraavan komennon vain, jos edellinen onnistui, ja `;` ajaa seuraavan aina

## b) Dolly

Lisäsin ensin Debianin julkisen SSH-avaimen GitHubiin (Settings → SSH and GPG keys) ja testasin yhteyden:
```
cat ~/.ssh/id_ed25519.pub
ssh -T git@github.com
# Hi vuorinenn! You've successfully authenticated, but GitHub does not provide shell access.
```
![b-ssh](kuva)

Asensin Gitin, asetin nimen ja sähköpostin, kloonasin varaston SSH-osoitteella, tein muutoksen ja puskin sen:
```
sudo apt-get -y install git
git config --global user.name "Mikael Vuorinen"
git config --global user.email "SÄHKÖPOSTI"
git clone git@github.com:vuorinenn/sunshine.git
cd sunshine
echo "Tämä rivi lisättiin Debianista gitillä." >> README.md
git add --all && git commit -m "Add line to README from Debian"
git pull && git push
```
![b-push](kuva)

Muutos näkyi GitHubin weppiliittymässä. Rivi näkyi samassa kappaleessa edellisen kanssa, koska Markdown yhdistää peräkkäiset rivit.

![b-github](kuva)

## c) Doh!

Tein tyhmän muutoksen: lisäsin README:hen rivin ja poistin LICENSE-tiedoston, mutta en commitoinut:
```
echo "TYHMÄ MUUTOS, ei saa jäädä" >> README.md
rm LICENSE
git status
git diff
```
Kumosin muutokset:
```
git reset --hard
# HEAD is now at c5b1de3 Add line to README from Debian
git status
# nothing to commit, working tree clean
ls
cat README.md
```
LICENSE palasi ja tyhmä rivi katosi. git reset --hard hävittää commitoimattomat muutokset lopullisesti, eikä siinä ole peruutusnappia.

## d) Tukki

```

```
git log --patch näytti commitin muutokset: plus-merkillä alkava rivi on lisätty. Huomasin, että sähköpostiksi oli jäänyt kirjaimellisesti "SÄHKÖPOSTI", koska unohdin vaihtaa sen b-kohdassa. Siksi GitHubissa näkyi commitin kohdalla kaksi eri kuvaketta.

![d-log](kuva)

echo "Sähköposti korjattu." >> README.md
git add --all && git commit -m "Test commit with corrected email"

Uudessa commitissa näkyy oikea sähköposti ja vanhassa edelleen SÄHKÖPOSTI. Vanhaa committia en muuttanut, koska historiaa ei kannata kirjoittaa uudelleen.

## e) Gitansible

Laitoin Ansible-kansion versionhallintaan:
```
cd ~/ansible
git init
git add --all
git commit -m "Add Ansible configuration to version control"
```
![e-init](kuva)

Muutin motd-roolin tervetuloviestiä, tarkistin muutoksen, ajoin Ansiblen ja commitoin:
```
sed -i 's/Tervetuloa! Tämä kone on Ansiblen hallinnassa./Tervetuloa! Tämä kone on Ansiblen ja Gitin hallinnassa./' roles/motd/tasks/main.yml
git diff
ansible-playbook site.yml
git add --all && git commit -m "Mention Git in welcome message"
git log --oneline
```
![e-diff](kuva)

Ansible-ajossa tuli changed=2: motd-rivi ja todennäköisesti hello-roolin /tmp/hello-ansible, koska /tmp tyhjenee uudelleenkäynnistyksessä. Huomasin, että /etc/motd-tiedostoon jäi myös vanha rivi, koska lineinfile vain lisää uuden rivin eikä poista vanhaa.
