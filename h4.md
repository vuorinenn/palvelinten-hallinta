# h4 Pizza Fantasia

Ympäristö: Windows 10, VirtualBox, Debian 13 (sama kone kuin aiemmissa tehtävissä). Tehty 16.–17.11.2026.

## x) Lue ja tiivistä

Karvinen 2023: Configuration Management of Distributed Systems over Unreliable and Hostile Networks, luvut 4.12.1, 4.12.2 ja 4.12.3.1.

### 4.12.1 Size and Complexity of Some DSLs
- Saltissa on 510 toimintoa ja Puppetissa 113
- Saltin dokumentaatiossa on yli 20 000 riviä ja 75 000 sanaa, eli se on pidempi kuin väitöskirja
- Oma huomio: Yllätti, että Saltin dokumentaatio on pidempi kuin kokonainen väitöskirja

### 4.12.2 Use of DSL Functions in Case Configuration
- Tero tutki kahta oikeaa konfiguraatiota: United States Government Configuration Baseline (NIST 2016) ja Mozilla Release Engineering Puppet Manifests (Mitchell ym. 2020)
- Yleisimmät toiminnot olivat case, file, package, service, exec ja augeas
- Kaikkia satoja toimintoja ei tarvita, vaan muutamalla hoidetaan suurin osa
- Oma huomio: Tulos sopii omaan kokemukseen, itse käytin h1–h4:ssä eniten package-, file- ja service-moduuleja

### 4.12.3.1 Dependencies Between Main Functions
- Vain exec ja file vaikuttavat suoraan koneeseen, muut toiminnot rakentuvat niiden päälle
- Idempotenssi saadaan aikaan if-rakenteilla, esim. tiedosto luodaan vain jos sitä ei ole olemassa
- Oma huomio: Huomasin saman h2:ssa, kun Ansiblen apt epäonnistui ja sama apt-get käsin näytti oikean virheen

## a) Räpylä

Valitsin MariaDB:n, koska se ei käytä porttia 80 eikä mene päällekkäin Nginxin kanssa.

```
sudo apt-get update
sudo apt-get -y install mariadb-server
sudo systemctl status mariadb --no-pager
sudo mariadb -e "SELECT VERSION();"
sudo mariadb -e "SHOW VARIABLES LIKE 'max_connections';"
sudo ss -tlnp | grep 3306
```
MariaDB 11.8.6 vastasi kyselyyn, max_connections oli oletuksena 151 ja mariadbd kuunteli porttia 3306.

<img width="1004" height="564" alt="image" src="https://github.com/user-attachments/assets/8c164db7-e3bf-4068-9cd6-043177d5851b" />


Kokeilin asetuksen muuttamista ensin käsin. Tein oman tiedoston kansioon /etc/mysql/mariadb.conf.d/:
```
sudo tee /etc/mysql/mariadb.conf.d/99-mikael.cnf > /dev/null <<'EOF'
[mysqld]
max_connections = 42
EOF

sudo systemctl restart mariadb
sudo mariadb -e "SHOW VARIABLES LIKE 'max_connections';"
```
Arvo muuttui 151 → 42.

## b) Automaatti

Tein roolin samalla package-file-service-mallilla kuin h3:ssa Nginxille (Karvinen 2026a).

```
$ tree -F roles/mariadb
roles/mariadb/
├── files/
│   └── 99-mikael.cnf
├── handlers/
│   └── main.yml
└── tasks/
    └── main.yml
```
```
$ cat roles/mariadb/files/99-mikael.cnf
# Ansiblen hallitsema tiedosto, muutokset ylikirjoitetaan
[mysqld]
max_connections = 42
```
```
$ cat roles/mariadb/tasks/main.yml
- apt:
    name: mariadb-server
    state: present
- copy:
    src: 99-mikael.cnf
    dest: /etc/mysql/mariadb.conf.d/99-mikael.cnf
    owner: root
    group: root
    mode: "0644"
  notify: restart mariadb
- service:
    name: mariadb
    state: started
    enabled: true
```
```
$ cat roles/mariadb/handlers/main.yml
- name: restart mariadb
  service:
    name: mariadb
    state: restarted
```
Lisäsin roolin site.yml:n loppuun ja ajoin:
```
ansible-playbook site.yml
sudo mariadb -e "SHOW VARIABLES LIKE 'max_connections';"
```
copy oli changed ja handler käynnisti MariaDB:n uudelleen. Arvo oli 42. apt-tehtävä näytti ok eikä changed, koska MariaDB-paketti oli jo asennettuna käsin tehdyn a-kohdan jäljiltä. Asennus tyhjästä näkyy d-kohdassa.

## c) Asetus

Muutin arvon herralla Ansible-kansion tiedostossa 42 → 77 ja ajoin uudelleen:
```
sed -i 's/max_connections = 42/max_connections = 77/' roles/mariadb/files/99-mikael.cnf
cat roles/mariadb/files/99-mikael.cnf
ansible-playbook site.yml
sudo mariadb -e "SHOW VARIABLES LIKE 'max_connections';"
```
Arvo muuttui. copy oli changed, handler käynnisti MariaDB:n uudelleen ja max_connections oli 77.

## d) Paikka remonttiin

Rikoin asennuksen poistamalla MariaDB:n purgella ja oman asetustiedoston:
```
sudo apt-get -y purge mariadb-server
sudo rm -f /etc/mysql/mariadb.conf.d/99-mikael.cnf
systemctl is-active mariadb
ls /etc/mysql/mariadb.conf.d/
sudo mariadb -e "SELECT VERSION();"
```
Purge kysyi, haluanko poistaa myös kaikki MariaDB:n tietokannat (/var/lib/mysql). Vastasin Yes.

![d-purge](kuva)

Tämän jälkeen MariaDB oli inactive, 99-mikael.cnf puuttui ja kysely antoi virheen:
```
ERROR 2002 (HY000): Can't connect to local server through socket '/run/mysqld/mysqld.sock' (2)
```
<img width="1004" height="570" alt="image" src="https://github.com/user-attachments/assets/729b4d09-dac0-466d-8815-cb76b9fd3ba7" />


Ajoin Ansiblen uudelleen:
```
ansible-playbook site.yml
systemctl is-active mariadb
sudo mariadb -e "SHOW VARIABLES LIKE 'max_connections';"
```
Ansible muutti kaiken takaisin. apt oli nyt changed eli paketti asennettiin tyhjästä, copy palautti asetustiedoston ja handler käynnisti palvelun. Tila oli active ja max_connections 77.

## e) Idempotentti

```
ansible-playbook site.yml
```
Tuli changed=0 eikä handleria ajettu. changed=0 todistaa, että kaikki on jo hoidettu eli kone on halutussa tilassa.
